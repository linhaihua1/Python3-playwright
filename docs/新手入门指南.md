## 一、先建立整体认知（5 分钟）

这是一个 **Web UI 自动化测试框架**，用 Python 驱动浏览器自动操作网页、校验结果。

### 1.1 它能做什么

写好"测试用例"后，一条命令就能让浏览器自动：
打开网页 → 登录 → 点菜单 → 上传文件 → 校验页面 → 生成报告。

它产出两种报告：

| 报告 | 给谁看 | 位置 |
|---|---|---|
| HTML 报告（中文） | 给人看，浏览器打开 | `Report/*.html` |
| JUnit XML | 给 Jenkins 流水线判定成败 | `Report/junit-results.xml` |

### 1.2 核心设计：四层分离

记住这一句话，后面所有代码都围绕它：

> **用例层管断言，页面对象管动作，基类管操作，元素表管定位。**

```
TestSuites/      用例层    ：写"测什么 + 断言结果"（不写 xpath、不写文案）
PageObject/      页面对象层：写"怎么操作页面"（一个方法 = 一个业务动作）
Common/basePage  基类      ：封装浏览器操作（唯一直接调 Playwright 的地方）
Common/elementPage 元素表  ：定位策略（"怎么找"）；界面文案从 config.ini [locators] 段取
```

**为什么要分层？** 举例：产品把「内容管理」菜单改名成「内容运营」——
你只需要改 `config.ini` 里**一行配置**，用例、页面对象、定位策略全都不用动。

### 1.3 配置优先，代码不写死

所有会变的东西都放在 `config.ini` 里，代码只读配置：

| 会变的东西 | 放在哪 |
|---|---|
| 被测地址、账号密码 | `[environment]`、`[testcase]` |
| 页面标题（断言用） | `[assert]`（支持关键字匹配，不用抄完整标题） |
| **按钮文字、菜单名**（元素定位用） | `[locators]` ← 换系统最常改的一段 |
| 用例在报告里的中文名 | `[case_names]` |
| 上传文件路径、查询关键字等业务数据 | `[testcase]` |

换环境、换账号、换系统都**改配置不改代码**。配置还能用环境变量覆盖（CI 靠这个注入密码）。

## 二、推荐的阅读顺序（从哪个文件看起）

按下面顺序读，由浅入深，每个文件读 10～20 分钟即可：

| 顺序 | 文件 | 读它的目的 | 重点看 |
|---|---|---|---|
| 1 | `README.md` | 30 秒了解工程是什么 | 快速开始那几行命令 |
| 2 | `run.py` | 看程序入口长什么样 | 它怎么解析参数、怎么调起执行器 |
| 3 | `TestSuites/testLogin.py` | **最该先读的文件**，看一条用例长什么样 | `setUpClass`、`test_1`~`test_6`、`check_title` |
| 4 | `PageObject/loginPage.py` | 看页面操作怎么封装成方法 | 每个方法对应一个业务动作 |
| 5 | `Common/elementPage.py` + `config.ini [locators]` | 看元素定位怎么配 | 文案在配置、策略在代码 |
| 6 | `Common/runner.py` | 看用例怎么被收集、执行、出报告 | `run()` 主流程、退出码 0/1/2 |

> 💡 新手**不要**一开始就啃 `Common/HTMLTestReportCN.py`（它是第三方报告模板，几千行，不用懂）。

## 三、第一次跑起来（10 分钟）

### 3.1 准备环境

```bash
# 1. 安装依赖（Playwright 自带浏览器与驱动）
pip install -r requirements.txt

# 2. 一次性下载 Playwright 自带浏览器（默认 chromium，装完即可跑）
python -m playwright install chromium
```

要求：Python 3.9+。**不用装 Chrome、也不用手动下任何浏览器驱动**——Playwright 会下载并自管自带浏览器（落在用户目录）。配置为 `edge` 时用系统已装的 Edge，`firefox` 需额外执行 `python -m playwright install firefox`。

### 3.2 准备配置

```bash
# Windows
copy config.ini.example config.ini
# Linux / macOS
cp config.ini.example config.ini
```

打开 `config.ini`，模板里每一项都写了注释和对应环境变量。最少要改的是：

```ini
[environment]
url = http://你的测试环境地址/portal        # 被测系统登录页

[testcase]
login_username = 你的账号
login_password = 你的密码
```

其余标了**必填**的项（`upload_file`、`query_keyword`、`phone`、`reporting`、
`[assert]` 三个标题、`[report]` 报告元信息……）模板已给了占位示例，
**换被测系统时要按实际情况改**——尤其 `[locators]` 段的按钮/菜单文案要照抄
被测系统页面上真实显示的文字。框架零硬编码，哪项没配或配错，启动时会直接报错
指明"缺哪个段哪个键、对应的环境变量叫什么"，按提示补即可，不会带着错值往下跑。

> ⚠️ `config.ini` 含明文密码，已被 `.gitignore` 排除，不会提交到代码库。

### 3.3 先跑冒烟（安全，不写数据）

```bash
python run.py --suite smoke
```

冒烟只跑前 3 条用例（登录 → 进系统 → 进素材库），**不会真的上传数据**，用来验证环境是否通。

看到类似输出就成功了：

```
==================== 测试结论 ====================
退出码 : 0
结果 : 通过
```

跑完看四处产物（默认开启了**产物隔离**：每次执行生成一个
`Report/<runId>/`、`Logs/<runId>/` 子目录，多次执行互不覆盖，并发构建也安全）：

| 想看什么 | 去哪看 |
|---|---|
| 详细报告 | 浏览器打开 `Report/<runId>/` 下最新的 `*.html` |
| 失败原因 | `Logs/<runId>/Error_Logs/*.log`（带模块名+行号） |
| 失败瞬间页面 | `img/<runId>/当天日期/*.png` |
| 给流水线的结果 | 与报告同目录的 `junit-results.xml` |

> 控制台的「执行结论」块里会直接打印 HTML 报告和 JUnit XML 的完整路径，照着打开即可。

## 四、怎么编写一条用例

假设你要在素材库里加一个"删除素材"的用例。**分三步，改三个文件**：

### 第 1 步：在 `[locators]` 段加界面文案（`config.ini`）

**大多数时候你只需要加一行配置**——框架内置了"按文字找按钮"等通用策略：

```ini
[locators]
; 删除按钮的文字（写「删除」也能命中页面上排版的「删 除」，框架自动去空格匹配）
btn_delete = 删除
; 确认弹窗按钮
btn_confirm_delete = 确定
```

页面对象里通过 `Config.locator('btn_delete')` 取用，框架自动拼出"跨 button/span/a/div
按文字匹配"的定位表达式。

> 💡 **什么时候才需要碰 `elementPage.py`？**
> 只有框架的通用策略覆盖不了时（比如要按 id 精确定位），才在那儿加新策略。
> 另有终极逃生门：在配置里写 `<键名>_xpath` 直接给完整定位表达式，一行配置覆盖框架策略：
>
> ```ini
> btn_delete_xpath = //button[@id='custom-delete']
> ```
>
> ⚠️ 无论哪种方式，都**不要**复制浏览器 F12 给的绝对路径 `/html/body/div[4]/...`，
> 那种页面多套一层 div 就失效。

### 第 2 步：在页面对象加动作（`PageObject/loginPage.py`）

```python
def delete_material(self):
    """删除列表第一条素材。"""
    self.click(Element1.delete_button)
    self.click(Element1.confirm_delete)
```

> 页面对象只写"动作"，**不写断言**。

### 第 3 步：在用例层加用例（`TestSuites/testLogin.py`）

```python
def test_7delete(self):
    """用例7：删除素材。"""
    case_name = self.case_names['delete']              # 中文名来自 [case_names] 配置
    log1.info('执行测试用例：%s' % case_name)
    self.login_page.delete_material()
    self.login_page.page_wait('delete_settle', 2)   # 等待时长读 [timing]，不写死
    self.check_title(case_name, self.title_material)   # 断言：标题来自 [assert] 配置
```

配套在 `config.ini` 加一行（值只影响报告显示）：

```ini
[case_names]
delete = 删除素材
```

> 四条铁律：
> 1. 方法名必须 `test_数字` 开头（`test_7...`），数字决定执行顺序。
> 2. 用例里**不写 xpath、不写界面文案、不写账号密码、不写断言期望值**，
>    全部来自 config.ini（`[locators]` / `[case_names]` / `[assert]` / `[testcase]`）。
> 3. 断言统一用 `self.check_title('用例名', 期望标题)`，失败会自动截图。
> 4. 等待页面渲染用 `self.login_page.page_wait('键名', 默认秒)`，秒数可被
>    `config.ini [timing]` 覆盖，**不要**直接写 `my_sleep(2)` 写死。

### 期望标题也能配置（不用抄完整标题）

如果你测的是别的系统、页面标题不同，不用改代码，改 `config.ini`：

```ini
[assert]
match_mode = contains          ; 匹配方式：exact（全等）/ contains（包含，默认）/ regex（正则）

; 只写**稳定不变的关键字**即可，标题带版本号、环境名都不会误判
title_login      = 统一门户
title_workbench  = 云媒资系统
title_material   = 素材库
```

新手最容易犯的错是把整个标题抄全（`工作台 - 云媒资系统 v2.3.1`）——
页面一升版断言就挂。`contains` 模式下只写`云媒资系统`这种稳定片段，一劳永逸。

> ⚠️ 这三项是**必填**配置（框架零硬编码，代码里没有兜底标题）：没配的话一启动就会报错
> `缺少必需配置：config.ini 的 [assert] title_login（对应环境变量 UI_ASSERT_TITLE_LOGIN）…`
> 并直接中止（退出码 2），按提示补齐即可 —— 这是保护，不是故障。

## 五、怎么执行用例

### 5.1 常用命令

```bash
python run.py --suite smoke                    # 冒烟（不写数据，推荐先跑这个）
python run.py                                   # 全量（⚠️ 会真实上传视频、提交数据）
python run.py --no-headless                     # 有界面跑，方便盯着看
python run.py --cases test_1login,test_2select_scxt   # 只跑指定用例
python run.py --url http://临时环境/portal       # 临时换被测地址
python run.py --title 我的报告 --filename my.html --mail   # 自定义报告名并发邮件
```

### 5.2 退出码（脚本/流水线靠它判断成败）

| 退出码 | 含义 |
|---|---|
| `0` | 全部通过 |
| `1` | 有用例失败或出错 |
| `2` | 环境/配置问题（没收集到用例、地址没配、浏览器起不来、**必填业务配置缺失**） |

查退出码：`echo $?`（Linux/Mac）或 `echo %errorlevel%`（Windows）。

### 5.3 验证框架本身（改了框架代码后必跑）

```bash
python tests/run_unit_tests.py
```

这套单元测试**不开浏览器、不联网、几秒跑完、零副作用**，专门验证框架代码没被改坏。
改完 `Common/` 或 `PageObject/` 里的代码，先跑它，绿了再去跑 UI 用例。

## 六、怎么接入 Jenkins

目标：让 Jenkins 在代码构建成功后，自动拉起冒烟测试并把结果显示在构建页面。

完整步骤见 [CI/CD 接入指南](CI-CD接入指南.md)，这里给你**最短路径 5 步**：

### Step 1：建 Jenkins 任务
`新建任务` → `Pipeline` → 命名 `ui-automation-smoke`
→ Pipeline 选 `Pipeline script from SCM` → SCM 选 Git 填仓库地址
→ **脚本路径填 `Jenkinsfile`** → 保存。

### Step 2：建两个凭据（存账号密码，加密且不进仓库）
`管理 Jenkins → 凭据 → 系统 → 全局凭据 → 添加凭据`，类型选 **Secret text**：

| 凭据 ID | 内容 |
|---|---|
| `ui-test-login-username` | 登录账号 |
| `ui-test-login-password` | 登录密码 |

### Step 3：装插件
确保装了 **JUnit**（必需）、**HTML Publisher**（推荐，看 HTML 报告）。

### Step 4：首次执行
点「Build with Parameters」，`TEST_SUITE` 选 `smoke`，`TARGET_URL` 填测试环境地址，`USE_CREDENTIALS` 保持 `true`，跑一次。

### Step 5：让构建成功后自动触发
在你的**构建任务**里加：`增加构建后操作步骤 → Build other projects → 填 ui-automation-smoke → 勾选 Trigger only if build is stable`。

完成后：构建成功 → 自动冒烟 → 构建页面出现「测试结果」和 HTML 报告链接 → 失败自动标红。

## 七、怎么接入 CI/CD 流水线

工程根目录的 `Jenkinsfile` 已经是一条完整的声明式流水线，4 个阶段：

```
① 拉取代码  →  ② 准备运行环境(建虚拟环境装依赖)  →  ③ 框架单元测试(质量门禁)  →  ④ 执行冒烟测试
                                                                          ↓
                                                              post: 出报告、归档、失败通知
```

### 7.1 核心机制：用环境变量注入配置（密码不落仓库）

流水线里不直接写账号密码，而是用 Jenkins 凭据注入成环境变量，自动覆盖 `config.ini`：

```groovy
withCredentials([
    string(credentialsId: 'ui-test-login-username', variable: 'UI_TESTCASE_LOGIN_USERNAME'),
    string(credentialsId: 'ui-test-login-password', variable: 'UI_TESTCASE_LOGIN_PASSWORD')
]) {
    sh 'python run.py --suite smoke --headless'
}
```

命名规则：`UI_` + 段名 + `_` + 键名（全大写）。例如：

| 配置项 | 对应环境变量 |
|---|---|
| `[environment] url` | `UI_ENVIRONMENT_URL` |
| `[testcase] login_password` | `UI_TESTCASE_LOGIN_PASSWORD` |
| `[ci] headless` | `UI_CI_HEADLESS` |

### 7.2 三种触发方式（按需选）

| 方式 | 场景 | 配置 |
|---|---|---|
| 上游构建触发 | 构建成功后自动冒烟（最常用） | 构建任务的 Post-build Actions |
| Webhook | 每次提交代码即冒烟 | 多分支流水线 + 仓库 Webhook |
| 定时回归 | 每晚跑全量 | 取消 `Jenkinsfile` 里 `triggers { cron(...) }` 的注释 |

### 7.3 推荐的执行策略

| 时机 | 跑什么 | 环境 |
|---|---|---|
| 每次提交/构建后 | `smoke` 冒烟 | 测试环境 |
| 每晚定时 | `full` 全量 | 测试环境 |
| 发布前 | `full` 全量 | 预发/生产（谨慎） |

> 💡 想在容器/Kubernetes 里跑（镜像已内置浏览器与系统依赖，节点首跑不用联网下载），用根目录的 `Dockerfile` 构建镜像，详见 [CI/CD 接入指南第十章](CI-CD接入指南.md#十容器化运行方案)。

## 八、新手最容易踩的坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 按钮明明在页面上却定位不到 | 配置的文案和页面不一致（页面常把按钮排成「报 送」带空格） | 确认 `config.ini [locators]` 里的文案与页面**真实显示的文字**一致（写「报送」即可，框架自动去空格匹配） |
| 某个元素定位永远失败 | `[locators]` 缺该键，框架退回了技术兜底定位，可能不准 | 在 `[locators]` 补该元素的文案，或用 `<键名>_xpath` 给精确表达式（日志会提示缺哪个键） |
| 启动即报 `缺少必需配置：config.ini 的 [段] 键`（退出码 2，用例没跑） | 必填业务配置缺失/为空 —— 零硬编码框架**刻意**的报错保护 | 按报错文案补 `config.ini`（或注入对应 `UI_段_键` 环境变量）；不要试图在代码里加默认值绕过 |
| 一条用例都没收集到（退出码 2） | 用例文件名不以 `test` 开头、缺 `__init__.py`、或大小写问题（Windows 不区分、Linux 区分） | 文件名统一小写 `test` 开头；确认 `TestSuites/__init__.py` 存在 |
| 元素全部定位不到 | 点「发布系统」会新开标签页，忘了切过去 | 确认调用了 `switch_other_window()` |
| 上传用例报文件不存在 | `config.ini` 里 `upload_file` 路径不对 | 改成真实存在的绝对路径 |
| 无头模式报元素找不到，有界面正常 | 窗口尺寸/渲染时机差异 | 调大 `[ci] element_timeout`（如 30） |
| Jenkins 上中文乱码 | 控制台编码 | 设 `PYTHONIOENCODING=utf-8`（`Jenkinsfile` 已设） |
| HTML 报告在 Jenkins 里样式错乱 | Jenkins CSP 限制 | 见 [CI/CD 接入指南 7.6](CI-CD接入指南.md#76-关于-html-publisher-的-csp-限制) |
| 改了用例方法名，冒烟少跑了 | `[ci] smoke_cases` 关键字失配 | 同步更新 `config.ini` 的 `smoke_cases` |

排错优先级：**控制台失败摘要 → `Error_Logs` 日志 → `img/` 失败截图 → HTML 报告**。
