# 接入新系统指南：让本框架跑任意主流 Web 系统

本框架已从"融媒体专用"升级为**通用 Web UI 自动化框架**，可适配党政、财务、ERP、商城、购物、信息系统、数据中台等市场上绝大多数 Web 系统。核心思路：**框架层完全通用，系统差异只在配置和薄薄一层页面对象**。

---

## 一、为什么能适配任意系统

框架做了两层解耦：

| 层 | 是否与具体系统相关 | 说明 |
|---|---|---|
| `Common/basePage.py` | 完全无关 | 浏览器操作 + 一套**跨系统通用方法**（按文本点击、按 placeholder 输入、下拉、表格行定位、等待加载等），所有系统通用 |
| `Common/runner.py` / `config.py` / `log.py` 等 | 完全无关 | 执行、配置、报告、CI 接入，全系统复用 |
| `PageObject/` + `TestSuites/` | 系统相关 | 每个被测系统在这里有自己的页面对象和用例；差异只在这一层 |

关键认知：**党政/财务/ERP/商城/数据中台虽然业务不同，但 UI 模式高度相似**——都是「用户名+密码登录 → 点菜单 → 填表 → 查询列表 → 按行操作」。把这些模式沉淀进 `basePage`，接入新系统时 80% 的操作直接复用。

---

## 二、两种接入方式

### 方式 A：零代码接入（推荐，适用于标准登录的系统）

如果你的系统登录页是常规的「用户名框 + 密码框 + 登录按钮」，**一行代码都不用写**，只改配置即可跑通用登录与基础操作。

**步骤：**

1. 打开 `config.ini`，填写 `[system]` 段（**前三项必填**，框架零硬编码、没有代码兜底值，
   缺任何一项 `GenericPage.login()` 都会立刻报错并告诉你缺哪个键）：
   ```ini
   [system]
   username_placeholder = 请输入用户名    # 【必填】登录页用户名框的灰色提示文字
   password_placeholder = 请输入密码      # 【必填】密码框的灰色提示文字
   login_button_text = 登录               # 【必填】登录按钮上的文字
   success_text = 退出                    # 可选：登录成功后页面必出现的文字；留空则等加载遮罩消失
   element_timeout = 15                   # 可选：该系统专属元素超时（技术参数，不配用全局值）
   ```
   同时填好 `[environment] url` 和 `[testcase] login_username / login_password`（均**必填**）。

2. 用例里这样写（`PageObject/genericPage.py` 提供的 `GenericPage`）：
   ```python
   from PageObject.genericPage import GenericPage

   gp = GenericPage(driver)
   gp.login()                     # 按配置完成登录
   gp.open_menu('系统管理', '用户管理')   # 按文字点多级菜单
   gp.fill_form({'请输入姓名': '张三', '请输入手机号': '13800138000'})  # 按 placeholder 填表
   gp.click_button('保存')         # 按文字点按钮
   row = gp.find_record('张三')     # 列表里按文本找到某一行
   ```

> 提示：`[system]` 的每一项也支持环境变量覆盖，如 `UI_SYSTEM_LOGIN_BUTTON_TEXT`，CI 上不用改文件。

### 方式 B：为复杂系统建专属页面对象

若系统登录方式特殊（验证码、扫码、SSO 跳转）或有大量特有页面，为它新建页面对象，**复用 `BasePage` 的全部能力**：

1. 在 `PageObject/` 新建 `erpPage.py`，继承 `BasePage`：
   ```python
   from Common.basePage import BasePage

   class ErpPage(BasePage):
       def open_purchase_order(self):
           self.click_by_text('采购管理')          # 跨系统通用方法
           self.click_by_text('采购订单')
           self.wait_loading_gone()                # 等加载遮罩消失
   ```
2. 元素定位优先用**稳定特征**（文字、placeholder、属性），少用绝对 xpath（抗改版）。
3. 在 `TestSuites/` 建 `testErp.py` 写断言。
4. 按系统切换执行：`python run.py --pattern testErp*.py`

## 三、跨系统通用能力清单（basePage 第七节）

接入新系统时最常用的方法，全部系统通用：

| 方法 | 用途 | 适用场景 |
|---|---|---|
| `click_by_text(text)` | 按可见文字点击 | 点按钮、菜单、tab、链接（**首选**） |
| `get_element_by_text(text)` | 按文字取元素 | 校验某文字是否出现 |
| `type_by_placeholder(ph, value)` | 按 placeholder 填输入框 | 90% 的表单填写 |
| `select_option(sel, text=)` | 选原生下拉框 | 表单下拉 |
| `wait_loading_gone()` | 等加载遮罩消失 | 点查询/保存后必等，防偶发失败 |
| `find_row_by_cell_text(text)` | 表格中按文本找行 | 列表页定位要操作的记录 |
| `get_table_rows()` | 取所有表格行 | 数据断言 |
| `hover(selector)` | 鼠标悬停 | 展开二级菜单 |
| `scroll_to(selector)` | 滚动到元素 | 长列表定位 |

> 经验：定位优先级 `文字 > placeholder/属性 > 相对 xpath > 绝对 xpath`。越靠前越抗改版、越能跨系统复用。

## 四、接入新系统的检查清单

1. ✅ `config.ini`：填 `[environment] url`、`[testcase]` 账号、`[system]` 文案特征、`[assert]` 各页面标题
   —— 这些都是**必填项**：框架零硬编码，缺配会直接报错（退出码 2）并指明该配哪个键/环境变量，
   按提示补即可；接入新系统本来就**只需要动配置**，这正是设计目的
2. ✅ 简单系统 → 直接用 `GenericPage`（方式 A）
3. ✅ 复杂系统 → 新建 `PageObject/xxxPage.py` 继承 `BasePage`，写业务动作（不写断言、不写 xpath 字符串）
4. ✅ `TestSuites/testXxx.py` 写用例，断言收敛到统一方法，失败自动截图
5. ✅ 本机 `python run.py --pattern testXxx*.py` 验证通过
6. ✅ 提交前确认 `config.ini` 未入库（`.gitignore` 已排除），真实账号走环境变量
7. ✅ 接 Jenkins：见 `docs/CI-CD接入指南.md`，密码由凭据注入

## 五、为什么不需要为每个系统改框架

- **执行器、报告、日志、CI 接入**：与系统无关，永远复用
- **浏览器操作**：`BasePage` 通用，新增的跨系统方法覆盖了主流 UI 模式
- **系统差异**：只存在于「配置的文案/地址/账号」和「薄薄一层页面对象」

因此接入第 N 个系统的成本 = 填一份配置 + （可选）写一个页面对象，框架本身零改动。

## 六、多系统并行：`--system` 一键切换

接入多个系统后，不必手动来回改配置。在 `config.ini` 为每个系统建一个 `[system_名称]` 段，运行时用 `--system` 指定：

```ini
[system_erp]
url = http://erp-test/login
username = erp_tester
password = your_password
pattern = testErp*.py

[system_mall]
url = http://mall-test/
pattern = testMall*.py
```

```bash
python run.py --system erp     # 自动应用 ERP 的地址/账号，并按其 pattern 跑用例
python run.py --system mall    # 切到商城系统
```

段内可用键：`url / browser / username / password / headless / pattern`，缺省键沿用全局配置。
命令行参数（如 `--pattern`）仍可在系统配置之上再覆盖，优先级：命令行 > 系统段 > 全局配置。

## 七、数据驱动：一组逻辑覆盖多组数据

同一业务想验证多组输入（多账号、多边界值）时，用数据驱动把数据与逻辑分离：

```python
from Common.dataDriver import data_driven, load_data

DATA = load_data('TestData/login_cases.csv')   # 支持 .csv / .json / .xlsx

class TestErpLogin(unittest.TestCase):
    @data_driven(DATA)
    def test_login(self, row):
        self.erp.login(row['username'], row['password'])
        # 报告里每组数据是一条独立用例
```

改数据只改数据文件，不改用例代码。

## 八、结果直达群：`--notify`

跑完把结果推送到钉钉/企业微信群，不用打开 Jenkins 也能第一时间知道成败：

```bash
python run.py --system erp --notify
```

只需在 `[notify]` 段填好机器人 `webhook`（钉钉加签再填 `secret`）。推送失败不影响测试结果。
